# 结论

Codex 的目标不是停留在“执行写代码”，而是向完整软件工程与更广义工作 Agent 扩张。它会自动完成需求归纳、PRD 草拟、代码考古、计划、实现、测试、评审和长期迭代，因此外部方法论与其能力存在真实重叠。

但必须区分：

```text
任务正确所需的信息 != 人工撰写这些信息的流程
```

模型变强会显著减少人工写 PRD、维护矩阵、复制 context pack 和操作 stage 的成本；不能消除目标、约束、决策授权、外部事实和成功判据本身。两个同样合理但价值取向不同的产品选择，无法仅靠更强推理唯一确定。

业界已有较强共识的是：复杂 Agent 任务需要环境事实、清晰目标、验证循环、停止条件和可评审证据。尚无共识的是：必须使用 SDD、固定 PRD/契约矩阵、特定阶段或 receipt schema。

因此方法论的长期核心不应是固定工作流，而应是可由未来 Agent 自动实现和检查的语义不变量：

1. 目标与非目标闭合；
2. 需要授权的决策闭合；
3. 跨模块承诺与责任闭合；
4. 验证和验收证据闭合；
5. 上游变化后的下游信任失效闭合。

未来最可能发生的是：SDD 的人工形式萎缩，Specification 的语义继续存在；方法论从“教 Agent 逐阶段填 artifact”转向“评价 Agent 是否已经获得并证明必要语义”。
